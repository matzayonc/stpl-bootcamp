# Writing slides

Slides exist to make one takeaway land, not to transcribe what the speaker
knows. Everything below serves that.

**Project rules win.** If the project has its own `style.md`, `CLAUDE.md`, or
reference deck, read it first — it carries the audience, language, and
narrative decisions this skill deliberately leaves open. This skill is the
craft floor, not a substitute.

## The slide

**Title** — one thought, 2–4 words. A label, not a summary; the body carries
the content. Noun phrase or short question both work.

**Bullets** — 3–5 per slide, one line each. A bullet that wraps to a second
line is a signal the slide is doing too much: cut it or split the slide. Bold
the one word per bullet a listener should retain (`\textbf{}`) — where it
helps, not as a quota.

**Helper block** — a slide that introduces or unpacks an idea ends with
**exactly one** block, chosen by semantic role:

| Block          | Use for                                       |
|----------------|-----------------------------------------------|
| `block`        | Definitions, key numbers, named formulas      |
| `alertblock`   | Problems, risks, things to watch for          |
| `exampleblock` | Effects, illustrations, real-world examples   |

Block bodies stay to 2–3 lines or a 3-item sub-list. If the helper needs more
than that, the helper *is* the slide.

No helper block on: transition slides, pure A-vs-B comparisons, summaries, and
the closing slide.

**Columns** — `\begin{columns}` only for direct opposition between two
parallel things (Before / After, Lender / Borrower, Option A / Option B). If
the halves do not contrast, stack blocks vertically instead.

## Deck skeleton

```
\maketitleframe                      % title slide
\begin{frame}{Plan} \tableofcontents % agenda
\section{...} + content frames       % body
\begin{frame}{Summary} ...           % recap, if more than one section
\makeclosingframe                    % mandatory sign-off — nothing after it
```

Section dividers are generated by `\AtBeginSection`. Never author one by hand.
Pick section names that read as standalone phrases — they render large.

## Reveals

Bullets reveal one at a time by default (`\beamerdefaultoverlayspecification{<+->}`).
Keep it on: it paces the speaker and stops the audience reading ahead.

Two opt-outs exist, and **both have a silent failure mode**. Read
`references/overlays.md` before writing any frame that is a diagram, a table,
or opens with a block — the bugs there do not produce LaTeX errors, only wrong
PDFs.

## Math and code

- Displayed equations (`\[ ... \]`) go inside a `block` titled with the
  formula's name. Worked numbers go in a separate `exampleblock`.
- Inline `$x$` for variable references in prose.
- Snippets under ~10 lines, inside a titled `block`. Longer than that: split
  it, or show it live instead of on a slide.
- Code that reveals in step with bullets uses the `codeblock` card — see the
  `deck-branding` skill. Do **not** put `\pause` inside a listing in a normal
  `block`; it desyncs from the bullets and the per-line background goes ragged.

## Images

Use them when they carry a concept — architecture diagrams (prefer TikZ, see
the `deck-diagrams` skill), real screenshots of an interface the audience will
use, and sparing icons. Never stock photography or decoration that does not
serve what is on screen.

## Narrative

For how to sequence a section, introduce a term, and pick analogies, read
`references/narrative.md`. Read it before drafting a deck from scratch; skip
it when editing existing slides for wording.

## Before shipping

- [ ] Title is 2–4 words, names one thought
- [ ] 3–5 bullets, one line each, keyword bolded where useful
- [ ] Concept slide ends in exactly one helper block, right type for its role
- [ ] A new term is set up by a problem before it is named
- [ ] Columns used only for real A-vs-B opposition
- [ ] Reveals still incremental, or the opt-out is deliberate and tagged
      (`references/overlays.md`)
- [ ] Squint test: at half size, the eye lands on the most important element
- [ ] Specific numbers and quotes carry a muted citation
- [ ] Build is clean and the dedupe report is understood, not ignored
